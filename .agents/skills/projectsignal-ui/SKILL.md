# ProjectSignal UI skill

Use whenever creating or changing product or marketing UI.

1. Start from the sales task: what decision must the user make after looking at this surface?
2. Preserve the design thesis: technical sales instrument, not generic AI dashboard.
3. Use domain structure: project stage, specification window, stakeholder route, product fit, modelled value.
4. Use the existing token palette and IBM Plex typography. Do not introduce purple gradients or Inter.
5. Prefer lines, columns and alignment over a grid of floating rounded cards.
6. Spend visual distinctiveness on one domain-specific element. Current signature: Signal Rail.
7. Use semantic color: orange = action/urgency, green = strong/confirmed signal, blueprint = analysis/context.
8. Keep frequent interactions instant or <=150ms. Never animate keyboard navigation. Respect reduced motion.
9. Use source-owned, accessible primitives; shadcn/Base UI style composition is preferred as complexity grows.
10. Data must answer “so what?”: show consequence, timing, relevance or next action next to the number.
11. Test mobile, keyboard focus, empty/loading/error states and table overflow before shipping.
